# Week 8 Demo 5 - Revision After Reality Contact

## Initial Plan

The project would allow:

* adding tasks
* marking tasks complete
* deleting tasks
* editing tasks
* saving tasks
* loading tasks
* progress analytics

---

## What Reality Showed

During testing, the student discovered that:

* task editing added too much complexity
* analytics were not essential for the first working version
* save/load behavior mattered more than extra features

---

## Revision

The project was reduced to:

* add task
* mark complete
* save tasks
* load tasks
* total planned minutes

---

## Why This Is a Good Revision

* the project became finishable
* the most useful features remained
* the code was easier to explain and test

---

## Teaching Point

Reality contact is not just "the code failed."

Reality contact also means discovering that the original feature plan was too large or poorly prioritized.
